# ครึ่งชั่วโมงแรก

สำหรับคนที่เพิ่งได้โฟลเดอร์นี้มาและยังไม่เคยทำงานกับ AI แบบเป็นทีม

---

## 1. ตั้งชื่อโปรเจกต์ (2 นาที)

```bash
./scripts/bootstrap.sh
```

มันจะถามชื่อโปรเจกต์ ชื่อแพ็กเกจ และ path ที่เก็บโค้ด แล้วแทนที่ตัวยึด `<...>` ให้ทั้งชุด
พร้อมสร้างไฟล์ทะเบียนอนุมัติที่ `~/.claude/approvals/registry.jsonl`

## 2. เติม `CLAUDE.md` (10 นาที) — ข้อนี้สำคัญที่สุด

เปิดแล้วเติมสามหัวข้อ

**หัวข้อ 1 โปรเจกต์** — ระบบนี้คืออะไร ใครใช้ ภาษาอะไร ที่เก็บโค้ดอยู่ไหน

**หัวข้อ 2 แหล่งความจริง** — เอกสารไหนคือคำตอบสุดท้ายเมื่อมีข้อขัดแย้ง ถ้ายังไม่มี ให้เขียนว่า
"ยังไม่มี — ถามเจ้าของงาน" ดีกว่าปล่อยว่าง

**หัวข้อ 3 มติที่ตัดสินแล้ว** — เรื่องที่เลือกไปแล้วและไม่ต้องการให้ใครมาถกใหม่ **พร้อมเหตุผล**

> ทำไมต้องมีเหตุผล: เคยมีกรณีที่เจ้าของงานตั้งใจให้ลำดับแท็บต่างจากต้นแบบ พอไม่ได้จดเหตุผลไว้
> รอบเก็บตกในอีกสองวันก็เกือบ "แก้ให้ตรงมาตรฐาน" แล้วรื้อสิ่งที่ตั้งใจให้ต่าง

## 3. ตั้งคำสั่งตรวจ (10 นาที)

เปิด `scripts/verify-fast.sh` และ `scripts/verify-full.sh` แล้วใส่คำสั่งของกองเทคโนโลยีคุณ
ตัวแปรอยู่บนสุดของไฟล์ มีคอมเมนต์บอกไว้

ตัวอย่าง Python: `ruff check` / `pytest -q` / `ruff format --check`
ตัวอย่าง Node: `npm run lint` / `npm test` / `npm run typecheck`

**`verify-full.sh` คือประตูออก** ทุกงานต้องแปะผลรันของมันก่อนถือว่าเสร็จ

## 4. ลองสั่งงานจริงหนึ่งชิ้น (5 นาที)

เปิด Claude Code ในโฟลเดอร์นี้ แล้วพิมพ์อะไรก็ได้ที่คุณอยากได้จริง ๆ

จาร์วิสจะ **ถามให้ชัดก่อนลงมือ** ถ้ามันเริ่มเขียนโค้ดทันทีโดยไม่ถามอะไรเลยกับโจทย์ที่กำกวม แปลว่า
`CLAUDE.md` ยังไม่ถูกอ่าน — ตรวจว่าไฟล์อยู่ที่รากของโฟลเดอร์จริง

## 5. เสียบ CI และล็อกสาขา (10 นาที) — ข้ามได้ แต่อย่าข้ามนาน

ทั่วทั้งชุดนี้เขียนไว้ว่า *"hook ทำให้การปลอมทิ้งร่องรอย ไม่ใช่ทำให้ปลอมไม่ได้ ตัวบังคับจริงคือ CI
บนสาขาที่ป้องกันไว้"* — **จนกว่าคุณจะทำขั้นนี้ ประโยคนั้นยังเป็นแค่คำพูด**

เหตุผลตรง ๆ: เอเจนต์มีสิทธิ์เขียนไฟล์ทั้งเครื่อง รวมถึงไฟล์ hook และไฟล์ตั้งค่าที่ลงทะเบียน hook ไว้
มันจึงปิดด่านของตัวเองได้ **แต่มันแก้สิ่งที่รันบนเซิร์ฟเวอร์ของ CI ไม่ได้**

**คัดลอกตัวอย่างไปใช้** — `ci-examples/github-actions.yml` ไปที่ `.github/workflows/`
หรือ `ci-examples/azure-pipelines.yml` ไปที่รากของ repo ทั้งสองไฟล์ทำด่านเดียวกัน 4 ด่าน:
เอกสารที่บอกว่าอนุมัติแล้วต้องมีคีย์ในทะเบียนจริง · ประตูออกของโปรเจกต์ · ไม่มีตัวยึดหลงเหลือ ·
เทสต์ของด่านอัตโนมัติเอง

**ด่านแรกคือหัวใจ** และมันถูกทดสอบแล้วว่าจับของปลอมได้จริง — เอกสารที่อ้างคีย์ที่ไม่มีในทะเบียน
ทำให้ CI แดงพร้อมระบุชื่อไฟล์และคีย์นั้น ในเครื่องคุณเองก็ตรวจแบบเดียวกันได้ด้วย
`python3 scripts/verify_approvals.py` — ทะเบียนหายไปทั้งไฟล์จะ**แดงดัง ๆ** ไม่ใช่ผ่านเงียบ ๆ

**ทะเบียนอนุมัติอยู่นอก repo** (`~/.claude/approvals/registry.jsonl`) เพราะถ้าอยู่ใน repo เอเจนต์
ก็เขียนได้ ต้องให้ CI อ่านจากที่ที่ทีมเก็บไว้ — ใส่เป็น secret ชื่อ `APPROVAL_REGISTRY` หรือเก็บใน
repo แยกที่เขียนได้เฉพาะคน

**ล็อกสาขา** ที่ GitHub: Settings → Branches → Add rule → require status checks to pass ·
ที่ Azure DevOps: Repos → Branches → Branch policies → Build validation

**ถ้ายังไม่ล็อกสาขา ด่านทั้งหมดยังข้ามได้ด้วยการ push ตรง** — ขั้นตอนนี้คือขั้นที่เปลี่ยนกฎให้เป็นการบังคับ

## สิ่งที่จะเกิดขึ้น และทำไม

**มันจะไม่ทำงานรวดเดียวจบ** — จะหยุดให้คุณอนุมัติเป็นช่วง ๆ นั่นคือสิ่งที่ตั้งใจ ไม่ใช่ความช้า
เพราะเอกสารที่ไม่มีใครอ่านก่อนลงมือ คือโค้ดที่ต้องรื้อทีหลัง

**มันจะขอให้คุณเป็นคนอนุมัติเอง** ด้วยคำสั่งสั้น ๆ ที่ขึ้นต้นด้วย `!` ในช่องแชท:

```
!scripts/approve.sh --list                    # อะไรรออนุมัติอยู่บ้าง
!scripts/approve.sh <slug> --by <ชื่อคุณ>      # อนุมัติ พร้อมประทับเอกสารและลงทะเบียน
```

(export `APPROVER=<ชื่อคุณ>` ไว้ครั้งเดียวแล้วไม่ต้องพิมพ์ `--by` อีก — สคริปต์จงใจ**ไม่มีชื่อ default**
เพราะลายเซ็นสำเร็จรูปไม่ใช่ลายเซ็น)

สคริปต์นี้ปฏิเสธเอกสารที่ยังไม่เข้ารูปโดยบอกว่าติดข้อไหน — ไม่มีหัวข้อ `## Approval history`,
มีบรรทัด `Status:` เกินหนึ่ง, git ยังไม่ track — และถ้าอนุมัติทีละหลายฉบับ **มีเสียสักไฟล์เดียว
ทั้งชุดจะไม่ถูกเขียนเลย** มันไม่ถามยืนยันซ้ำ เพราะช่อง `!` ไม่มี tty — เวอร์ชันแรกที่ถาม
`confirm? [y/N]` ล้มทุกครั้งที่ใช้จริงทั้งที่หน้าตาเหมือนการปฏิเสธ

เอเจนต์เขียนทะเบียนเองไม่ได้ มี hook กันไว้ **และจาร์วิสจะไม่เซ็นแทนคุณแม้คุณอนุญาต** เพราะพอปลอมได้
ครั้งเดียว บันทึกอนุมัติทั้งชุดก็เชื่อไม่ได้อีก และสคริปต์นี้ไม่ได้เปลี่ยนกติกานั้น — มันย่อแค่การพิมพ์
ไม่ได้ย่อความไว้วางใจ: คนที่รันต้องเป็นคุณ

**มันจะบอกเมื่อทำผิด** รวมถึงตอนที่มันเถียงคุณแล้วมันผิดเอง — ถ้ามันเงียบเรื่องความผิดพลาดของตัวเอง
ให้ทวงทันที เพราะรายงานที่กรองแล้วคือรายงานที่ใช้ตัดสินใจไม่ได้

| สถานการณ์ | เรียก |
|---|---|
| มีไอเดีย ยังไม่รู้ว่าจะทำอะไรก่อน | `pm` |
| รู้ว่าจะทำอะไร ยังไม่รู้ว่าหน้าตาแบบไหน | `ba-sa` |

คุณไม่ต้องจำ — บอกจาร์วิสว่าอยากได้อะไร มันจัดให้

## ข้อผิดพลาดที่คนใหม่เจอบ่อยที่สุด

**1. อนุมัติสเปกโดยยังไม่อ่าน** เพราะอยากให้งานเดิน — แล้วได้ของที่ไม่ต้องการมาทั้งก้อน
ถ้ายังไม่พร้อมอ่าน บอกว่า "ขอเวลาอ่านก่อน" จาร์วิสจะไปทำอย่างอื่นที่ไม่ติดประตูนั้นแทน

**2. เชื่อคำว่า "เสร็จแล้ว" โดยไม่ดูผลรัน** — ให้มองหาผลรันจริงเสมอ ไม่มีผลรัน = ยังไม่เสร็จ

**3. ถามหลายเรื่องในข้อความเดียว** — คำตอบจะหายไปหนึ่งข้อเสมอ จาร์วิสถูกตั้งให้ถามทีละข้อ
พร้อมคำแนะนำ ขอให้คุณตอบแบบเดียวกัน

**4. ปล่อยให้เอเจนต์หลายตัวแก้ไฟล์เดียวกัน** — บอกจาร์วิสว่าไฟล์ไหนสำคัญ มันจะจัดคิวให้
