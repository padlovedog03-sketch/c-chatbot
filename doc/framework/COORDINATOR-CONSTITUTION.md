# ธรรมนูญผู้สั่งการ (Coordinator Constitution)

Status: Living
Upstream: [`NORTH-STAR.md`](NORTH-STAR.md) กลไก ๓ — โดยเฉพาะสัจธรรม ๓ (*"ผู้ถืออำนาจสูงสุดคือผู้เดียวที่ไม่มีใครตรวจ"*)

---

## ขอบเขต: สัญญา ไม่ใช่คำสั่งเฉพาะเครื่องมือ

เอกสารนี้เป็นเนื้อหาชั้น ๒ (สัญญา) ตาม [`RUNTIME-CONTRACT.md`](RUNTIME-CONTRACT.md) — บอกว่า
**ผู้สั่งการต้องรับผิดชอบอะไร และมีอะไรตรวจได้**  ไม่บอกว่า "AI ตัวไหนต้องทำอะไร" เพราะผู้สั่งการที่ข้อนี้
ผูกไว้อาจเป็นมนุษย์ที่รันสคริปต์ด้วยมือ เป็นปัญญาประดิษฐ์หนึ่งตัว หรือฝูงเอเจนต์หลายตัวที่ผลัดกันคุมงาน —
ทั้งสามแบบต้องอยู่ใต้ข้อบังคับเดียวกัน กฎในนี้จึงพูดถึง **บทบาทผู้สั่งการ** เสมอ ไม่เอ่ยชื่อผลิตภัณฑ์ใด

สัจธรรม ๓ ของ NORTH-STAR ระบุเหตุผลที่เอกสารนี้ต้องมีอยู่: ใส่การกำกับให้ผู้ปฏิบัติครบทุกคนแล้วลืม
ผู้สั่งการ ผลที่วัดได้คือผู้สั่งการยืนยันข้อมูลผิดซ้ำแล้วซ้ำเล่าโดยไม่เคยจับตัวเองได้ ทุกครั้งที่ความผิดถูกจับได้
คนจับคือผู้ใต้บังคับบัญชาหรือเจ้าของงาน — **นี่คือคุณสมบัติของตำแหน่ง ไม่ใช่เรื่องนิสัย**

---

## หลักการอ่านตาราง

แต่ละกฎมี 4 คอลัมน์:

- **หน้าตาของการละเมิด** — ตัวอย่างที่จับต้องได้ ไม่ใช่คำจำกัดความ
- **หลักฐานที่จับได้** — สิ่งที่ต้องมองหาเพื่อจับการละเมิดนั้น
- **บังคับด้วยเครื่องได้ไหม** — ใช่/ไม่ พร้อมเหตุผล
- **ถ้าไม่ได้: ช่องรายงานตัวเองที่บังคับให้มี** — ตาม RUNTIME-CONTRACT ข้อ "ประกาศเองว่ากันอะไรไม่ได้"

**สิ่งที่ต้องพูดตรง ๆ ก่อนอ่านต่อ:** ทุกกลไกในนี้ตรวจ**ไวยากรณ์**ของคำอ้าง ไม่ตรวจ**ความจริง**ของมัน —
เหมือนที่ `scripts/verify_approvals.py` ตรวจว่าคีย์อนุมัติมีอยู่ในทะเบียนจริง แต่ตรวจไม่ได้ว่ามนุษย์ตั้งใจ
อนุมัติจริงหรือกดผ่านไปเฉย ๆ เครื่องมือในเอกสารนี้จับได้แค่ **"อ้างจำนวนโดยไม่แปะป้ายที่มาตามรูปแบบที่กำหนด"**
ไม่ใช่ **"อ้างจำนวนผิด"** — คนละอย่างกัน และยังต้องมีมนุษย์หรือเอเจนต์อีกตัวอ่านของจริงอยู่ดี (กลไก ๖)

## ตารางข้อบังคับทั้ง 5 ข้อ

| # | กฎ (จาก NORTH-STAR กลไก ๓) | หน้าตาของการละเมิด | หลักฐานที่จับได้ | บังคับด้วยเครื่องได้ไหม |
|---|---|---|---|---|
| 1 | ห้ามอ้างจำนวนจากการมองที่เห็นไม่ครบ | "ไม่มี X" หรือ "เจอ N ตัว" ที่มาจากคำสั่งมี `head`/`tail`/`2>/dev/null`/`-m N`/`--max-count`/`[:n]` | คำอ้างจำนวนที่แปะป้าย `MEASURED:` แต่คำสั่งข้างใต้ตรงกับรูปแบบตัดตอน | **ใช่ (บางส่วน)** — ตรวจได้ว่าคำสั่งที่แปะมาตัดตอนหรือไม่ ตรวจไม่ได้ว่าคำอ้างที่ไม่แปะคำสั่งมาด้วยนั้นถูกตัดตอนจริงหรือเปล่า (เพราะไม่มีคำสั่งให้ดู) — ข้อนี้จับได้แค่ "ไม่แปะ" ไม่ใช่ "ตัดตอน" เมื่อไม่มีคำสั่งให้เห็น |
| 2 | ห้ามบรรยายสถานะจากความจำ — วัดใหม่ทุกครั้งก่อนพูด | รายงานสถานะ repo/ระบบโดยไม่มีผลรันคำสั่งแนบมา หรือใช้ผลรันเก่าข้ามรอบ | — (ไม่มีสิ่งที่ตรวจได้จากข้อความ; "นึกออกจากความจำ" ไม่ทิ้งลายเซ็นต่างจาก "วัดใหม่แล้วพิมพ์เหมือนเดิม") | **ไม่ได้** — ต้องใช้ช่องรายงานตัวเอง |
| 3 | ห้ามส่งต่อตัวเลขของผู้อื่นโดยไม่ติดป้าย | พิมพ์ตัวเลขที่มาจากเอเจนต์/รายงานอื่นเหมือนเป็นของตัวเอง ไม่มีป้าย `RELAYED:` หรือ `MEASURED:` ซ้ำ | คำอ้างจำนวนที่ไม่มีป้ายกำเนิดใดเลย (`MEASURED:`/`INFERRED:`/`RELAYED:`) ตามหลัง | **ใช่** — ตรวจได้ว่ามีป้ายหรือไม่ ตรวจไม่ได้ว่าป้ายที่ใส่มาจริงหรือโกหก (เช่นเขียน `RELAYED:` ทั้งที่จริงไม่ได้รับต่อมา) |
| 4 | ทุกคำสั่งต้องระบุที่มา | สั่งผู้ปฏิบัติว่า "ห้ามแก้ไฟล์ X" โดยไม่บอกว่าเป็นมติเจ้าของงาน เอกสารอนุมัติ หรือความเห็นตัวเอง | บรรทัดคำสั่ง (`INSTRUCTION:`) ที่ไม่มี `PROVENANCE:` ตามหลังจากสามค่า: `OWNER` / `APPROVED <path>` / `JUDGEMENT` | **ใช่ (ไวยากรณ์)** — ตรวจได้ว่าแปะป้ายที่มาหรือไม่ และถ้าอ้าง `APPROVED <path>` ตรวจได้ว่าไฟล์นั้นมีจริงและ `Status: Approved` จริง (หลักการเดียวกับด่านสั่งงานที่มีอยู่แล้วซึ่งกันการเรียกผู้ปฏิบัติให้ลงมือเมื่อสเปกต้นทางยังไม่อนุมัติ — ดูข้อ 5) ตรวจไม่ได้ว่า `JUDGEMENT` ที่อ้างนั้นสมควรจริงหรือเป็นการเดา |
| 5 | คำสั่งของผู้สั่งการแพ้เอกสารที่เจ้าของงานอนุมัติเสมอ | บรีฟผู้ปฏิบัติให้ทำสิ่งที่ขัดกับสิ่งที่สเปกอนุมัติแล้วสั่งไว้ | — (ตรวจความขัดแย้งทางความหมายระหว่างข้อความอิสระกับเนื้อหาสเปก ต้องใช้ความเข้าใจภาษา ไม่ใช่รูปแบบ) | **ไม่ได้ (โดยทั่วไป)** — มีส่วนย่อยที่บังคับด้วยเครื่องได้แล้วอยู่ก่อนแล้วในชั้นด่านตรวจ (ด่านสั่งงาน): บล็อกการสั่งให้ผู้ปฏิบัติลงมือเมื่อสเปกต้นทางยังไม่ `Approved` — นั่นคือชั้นเดียวที่มีอยู่จริง ส่วนที่เหลือ (บรีฟขัดกับ**เนื้อหา**ของสเปกที่อนุมัติแล้ว ไม่ใช่แค่สเปกยังไม่อนุมัติ) ต้องใช้ช่องรายงานตัวเอง |

## ไวยากรณ์ที่ตรวจด้วยเครื่อง (`scripts/coordinator_lint.py`)

ทำตามธรรมเนียมเดิมของคลังนี้ทุกอย่าง — บรรทัดนำหน้าที่ regex จับได้ตรง ๆ (แบบเดียวกับ `Status:`,
`Approval:`, `Entered:`, `Owner:`) **ไม่ใช่** การตรวจภาษาธรรมชาติแบบเดา เพราะการเดาความหมายจากประโยค
อิสระคือสิ่งที่ด่านตรวจคำสั่งเชลล์ตัวหนึ่งในคลังนี้เคยพังมาแล้วจากการจับคำแบบ substring (ดู `doc/framework/
WHY.md` ข้อ 5) — **บรรทัดที่ไม่ได้แปะป้ายตามรูปแบบนี้ ล่องหนต่อตัวตรวจโดยสมบูรณ์ นี่คือขีดจำกัดที่ประกาศไว้
ไม่ใช่ขีดจำกัดที่ซ่อนไว้** วินัยนี้เป็นแบบ opt-in จนกว่าทีมจะเอาไปเสียบเข้ากับเทมเพลตรายงานของตัวเอง

ป้ายกำเนิดสามคำ (`MEASURED`/`INFERRED`/`RELAYED`) **คือคำเดียวกับกลไก ๒ ของ NORTH-STAR**
(*วัดจริง / อนุมาน / รับต่อมา*) แปลงเป็นแท็กที่ regex จับได้ — ธรรมนูญนี้ไม่ได้คิดวินัยใหม่ มันคือกลไก ๒
ที่ถูกบังคับใช้เฉพาะกับผู้สั่งการ ตามที่กลไก ๓ ต้องการ

```
CLAIM: <ข้อความที่อ้างจำนวนหรือความไม่มี>
MEASURED: <คำสั่งที่รันจริงเพื่อได้ตัวเลขนี้>
```
```
CLAIM: <ข้อความ>
INFERRED: <สมมติฐานที่ใช้ + สิ่งที่จะทำให้ข้อสรุปนี้ผิด>
```
```
CLAIM: <ข้อความ>
RELAYED: <ชื่อแหล่ง — ยังไม่ตรวจซ้ำ>
```
```
INSTRUCTION: <คำสั่งที่ให้เอเจนต์>
PROVENANCE: OWNER | APPROVED <path/to/doc.md> | JUDGEMENT
```
```
SELF-REPORT:
RE-MEASURED: yes <อะไรที่รันใหม่> | no <เหตุผลที่ไม่จำเป็น>
CHECKED-AGAINST-APPROVED-DOCS: <รายชื่อเอกสาร หรือ "none applicable">
```

บล็อก `SELF-REPORT:` เป็นข้อบังคับต่อรายงานหนึ่งฉบับ (ไม่ใช่ต่อคำอ้างหนึ่งข้อ) — มันคือช่องรายงานตัวเอง
สำหรับกฎ ๒ และ ๕ ที่บังคับด้วยเครื่องไม่ได้โดยตรง `scripts/coordinator_lint.py` ตรวจได้แค่ว่า**ช่องนี้มีอยู่
และกรอกครบ** ไม่ใช่ว่าคำตอบในช่องเป็นความจริง — เหมือนที่ `## Approval history` ต้องมีอยู่ แต่ไม่มีอะไร
พิสูจน์ได้ว่ามนุษย์อ่านก่อนอนุมัติจริง

## สิ่งที่สัญญานี้ไม่รับประกัน

ใช้กลไก ๔ ข้อ ๓ ของ NORTH-STAR กับตัวเอง:

- **ไม่รับประกันว่าป้ายที่แปะเป็นความจริง** — เขียน `MEASURED:` ทับคำสั่งที่ไม่ได้รันจริงก็ผ่านตัวตรวจนี้
  ได้ เพราะตัวตรวจอ่านแค่ว่าป้ายกับคำสั่งอยู่คู่กันตามรูปแบบ ไม่ได้รันคำสั่งนั้นซ้ำเพื่อยืนยัน
- **ไม่รับประกันว่าจะจับ "อ้างจำนวนไม่ครบ" ทุกครั้ง** — ถ้าไม่แปะ `CLAIM:` เลย ตัวตรวจไม่เห็นบรรทัดนั้น
  ตั้งแต่ต้น กฎข้อ 1 จึงจับได้เฉพาะคำอ้างที่**เข้าสู่ระบบไวยากรณ์นี้แล้ว**เท่านั้น
- **ไม่แทนที่กลไก ๖ (อาณัติค้าน)** — ผู้ตรวจอิสระที่อ่านของจริงยังจำเป็นอยู่ดี เครื่องมือนี้แค่ทำให้
  "ไม่มีป้ายเลย" เป็นสิ่งที่เห็นได้ก่อนถึงมือผู้ตรวจ
- **กฎ ๒ และ ๕ ไม่มีการบังคับด้วยเครื่องจริงในความหมายกว้าง** มีแค่ช่องรายงานตัวเองแบบบังคับให้มี
  (ไม่บังคับให้จริง) — ผู้สร้างธรรมนูญนี้ประกาศไว้ตรง ๆ แทนที่จะปล่อยให้มีคนมาพบเอง

เอกสารนี้คือกฎที่เขียนแล้ว*
